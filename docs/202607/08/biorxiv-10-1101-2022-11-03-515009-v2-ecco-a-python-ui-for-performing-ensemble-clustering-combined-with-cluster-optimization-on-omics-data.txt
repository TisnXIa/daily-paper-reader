Abstract Modern biological research often leverages clustering to elucidate disease endotypes 12 

and underlying mechanisms. Mono-cluster solutions remain the predominant method; however, 13 

this approach has concerning pitfalls, motivating the need for ensemble clustering methods. We 14 

present Ensemble Clustering Combined with Cluster Optimization (ECCO), an open-source 15 

Python UI that provides a fast, scalable framework for ensemble clustering of large-scale data. It 16 

includes zero-code integration of novel ensemble clustering methods and many pre- and 17 

post-processing functionalities. This enables researchers to efficiently integrate advanced 18 

clustering methodologies into their analysis pipelines. 19 20 

## Introduction 21 

The ongoing omics revolution is dramatically changing biological research. Studies that once fea-22 

tured tens or hundreds of analytes now capture thousands, leading to a breadth of multi-omic 23 

analyses of diseases and their underlying mechanisms ( Barapour et al., 2026 ; Zhou et al., 2024 ). 24 

Complex diseases such as osteoarthritis are now thought to arise from interactions among multi-25 

ple biological pathways ( Wilson et al., 2025 ). These shifts require researchers to leverage advanced 26 

bioinformatic techniques to understand these datasets and identify biological mechanisms of dis-27 

ease and disease heterogeneity ( Ronan et al., 2016 ). As large-scale multi-omics studies become 28 

mainstream, there is a critical need for efficient, validated implementations of the latest analytical 29 

methods. 30 

Clustering is an unsupervised machine learning approach that has become a critical part of 31 

biological studies ( Oghabian et al., 2014 ; Chen et al., 2024 ; Barapour et al., 2026 ; Hislop et al., 32 

2022 ; Wallace et al., 2022 ; Welhaven et al., 2024 ). For example, our lab has used clustering to iden-33 

tify novel metabolic endotypes of osteoarthritis ( Wallace et al., 2022 ), rapid shifts in synovial fluid 34 

metabolism, sex-specific differences in metabolic profiles after joint injuries ( Welhaven et al., 2024 ;35 

Hislop et al., 2022 ), and changes in cortical bone metabolism in chronic kidney disease ( Stauffer 36 

et al., 2026 ). However, each clustering approach comes with its own set of assumptions and limita-37 

tions that directly impact the resulting biological insight, meaning an analytical choice could impact 38 

a field’s direction (or misdirection). This challenge has been exacerbated by modern-day omics ex-39 

periments where thousands of analytes are measured, leading to the curse of high-dimensionality, 40

To mitigate these 41 

challenges, recent studies have suggested using ensemble clustering approaches ( Ronan et al., 42 

2016 ). Ensemble clustering aggregates results from multiple clustering algorithms to determine 43 

the observations that consistently cluster together ( Golalipour et al., 2021 ). Before combining the 44 

cluster solutions into an ensemble, the number of clusters must be specified or determined using 45 

an internal clustering metric (e.g., Average Silhouette Metric). One approach to combining cluster 46 

solutions is voting consensus, in which each pair of observations is assigned a weight based on 47 

how consistently they cluster together across all cluster solutions. For example, a pair that clus-48 

ters together in every solution receives a weight of 1 ( Golalipour et al., 2021 ). Ensemble clustering 49 

has strong potential to broadly improve bioinformatic analysis; however, it has yet to be widely 50 

adopted despite the availability of two coding libraries ( Chiu and Talhouk, 2018 ; Ronan et al., 2018 ). 51 

A potential explanation for this is the lack of an easy-to-use user interface (UI) and the need for pro-52 

gramming expertise to implement. Therefore, we created an easy-to-use open-source Python UI 53 

that can be readily used by researchers of all backgrounds, with several key improvements: 54 

• Unix and Windows executables allow users to download and run the ECCO UI immediately. 55 

• Codeless generation of custom ensemble cluster solutions. 56 

• User-facing reports on cluster similarity and performance. 57 

• Multi-core processing that scales with available computational resources. 58 

• Various dissimilarity metrics for many types of biological data (Appendix - Figure 1, Appendix 59 

- Table 1). 60 

• Built on scipy and scikit-learn, allowing for rapid expansion to other clustering approaches. 61 

ECCO is an open-source Python UI providing key functionalities for clustering biological data that 62 

is scalable, user-friendly, and readily adaptable to the diverse needs of researchers. Users can run 63 

ECCO on their local computers or compute clusters, scaling the tool with their available computa-64 

tional power. The current version (v1.0.3) is intended to serve as a framework for expanding with 65 

additional mono-clustering algorithms, ensemble clustering methodologies, and rapid extraction 66 

and analysis of identified clusters. In addition, we offer a suite of 24 functionalities, including both 67 

pre- and post-processing tools within clustering pipelines and as standalone features (Appendix 1). 68 

Taken together, ECCO provides efficient ensemble clustering analyses and the framework for ex-69 

pansion into a generalizable tool for clustering biological data. 70 

## Methods: ECCO workflow. 71 

ECCO is a four-step workflow from data pre-processing to ensemble cluster generation (Figure 1). 72 

Users can perform ECCO by submitting an ensemble specification and corresponding data file (Fig-73 

ure 1, left), and selecting the data pre-processing they would like to perform. After submission, 74 

ECCO pre-processes the data, generates cluster solutions, and determines the number of clusters 75 

for each cluster solution based on the optimal value of an internal cluster metric, such as the clus-76 

ter solution with the Average Silhouette Width closest to 1 (Figure 1, middle). Finally, the consensus 77 

cluster solution (i.e., ensemble cluster solution) is calculated (Figure 1, middle), and users are pro-78 

vided with Rand and adjusted Rand index evaluations of each cluster solution, and clustergrams 79 

of the ensemble cluster solution (Figure 1, right). 80

## User Input: Ensemble Specification 95 

The ensemble specification file must contain the input parameters for the dissimilarity metric, link-96 

age function, internal cluster metric, and correlation coefficient or pairwise dissimilarity metric 97 

(Table 1). Users can customize the ensemble by adapting the input parameters in the specifi-98 

cation file. The current version of ECCO (v1.0.3) accepts all dissimilarity metrics available within 99 

scipy.spatial.distance, and linkage functions of agglomerative hierarchical clustering provided by 100 

sci-kit learn ( Pedregosa et al., 2011 ). Users need to specify an internal cluster metric for each clus-101 

tering methodology (Table 1) with three currently available: Calinski-Harabasz (CH) ( Caliński and 102 

Harabasz, 1974 ), Average Silhouette Width (SIL) ( Rousseeuw, 1987 ), and Davies-Bouldin Index (DBI) 103 

(Davies and Bouldin, 1979 ). To compare observations, users need to specify either a Pearson or 104 

Spearman correlation coefficient or add pw if they want to leverage a pairwise distance metric 105 

(e.g., Euclidean) among the observations (Table 1). See Appendix 1 for definitions of the available 106 

dissimilarity (Appendix Table 1 and internal cluster metrics. 107

Interpretation of Rand and Adjusted Rand Index 142 

Comparison of mono-cluster solutions (e.g., Complete linkage hierarchical cluster solution) is criti-143 

cal to understanding if similar observations are consistently clustering. ECCO automatically gener-144 

ates visuals for two well-accepted external cluster evaluation metrics, the Rand index ( Rand, 1971 )145 

and the adjusted Rand index ( Hubert, 1985 ). We also provide a separate functionality with other ex-146 

ternal cluster evaluation metrics, including the Normalized Mutual Information ( Danon et al., 2005 ), 147 

and adjusted Normalized Mutual Information ( Vinh et al., 2009 ). The Rand index determines clus-148 

ter similarity by determining if the cluster solutions agree on the observations that cluster together 149 

and those that do not cluster together, with 0 meaning no agreement between cluster solutions, 150 

and 1 meaning perfect agreement ( Rand, 1971 ). The adjusted Rand index corrects the Rand index 151 

for the agreement expected by chance ( Hubert, 1985 ), with values ranging from -1 to 1, and any-152 

thing less than 0 representing less agreement on clusters than expected. ECCO represents both 153 

the Rand and adjusted Rand index values with increasing bubble size and deepening red color as 154 

they go to 1. In our case study, we found that Rand index values varied from 0.31 to 1 (Figure 2A), 155 

suggesting cluster solutions ranged from minimal to perfect agreement. For the adjusted Rand 156 

index, we found that all mono-cluster solutions achieved greater than expected agreement, 0.04 157 

to 1 (Figure 2B). These results indicate a high diversity of cluster solutions, which is important to 158 

improve ensemble performance ( Golalipour et al., 2021 ). We next investigated whether an ensem-159 

ble cluster solution is necessary by comparing each mono-cluster solution to the ensemble cluster 160 

solution (Figure 2C). We found that a complete linkage cluster solution achieved strong agreement 161 

with the ensemble cluster solution, 0.92 Rand index, and 0.66 adjusted Rand index (Figure 2C). 162 

However, given 1362 metabolites were analyzed, a Rand index of 0.92 results in >100 metabolites 163 

not clustering as they do in the ensemble cluster solution, more than enough to impact pathway 164 

enrichment results. Therefore, in this case, users should use the ensemble cluster solution as it 165 

leverages evidence from all six cluster solutions to determine the cluster solution. 166 

Interpretation of Clustergrams 167 

ECCO outputs two clustergrams for visualization of the ensemble cluster solution, one of the co-168 

occurrence matrix and the other of the pre-processed data, with black dashed-line boxes repre-169 

senting the identified clusters (Figure 2D-E). The clustergram (Figure 2D) of the co-occurrence ma-170 

trix is colored from 0 to 1, with 1 representing metabolites sharing a cluster in each cluster solution. 171 

In our case study, we see several distinct yellow (yellow representing 1) squares (Figure 2D), sug-172 

gesting that, independent of the cluster solution, many metabolites always clustered together. This 173 

is consistent with our analysis of the Rand and adjusted Rand index, which suggested that the clus-174 

ter solutions were identifying similar clusters of observations. Finally, ECCO provides a visualization 175

## Discussion 191 

ECCO is a flexible, multifunctional UI that enables efficient calculation of ensemble cluster solutions 192 

along with pre- and post-processing capabilities for bioinformatic analyses. The defining function-193 

alities of ECCO are 1) the off-the-shelf usability of the UI, and 2) the ability to generate novel ensem-194 

bles with zero coding. Users can immediately use ECCO by simply downloading either Unix/Mac or 195 

Windows executables from Github (v1.0.3). Novel ensembles can be generated by updating a sin-196 

gle CSV file, and future versions will incorporate additional non-hierarchical clustering algorithms. 197 

Furthermore, our open-source codebase allows users to expand the UI’s functionality to meet their 198 

needs. Thus, the ECCO UI represents a critical open-source framework for implementing ensemble 199 

clustering for biological and non-biological analyses. 200 

ECCO UI contains a comprehensive suite of tools for data pre-processing, post-processing, clus-201 

tering, and internal and external cluster performance evaluation, with built-in logging and error 202 

handling. The UI handles missing data by automatically displaying an error and prompting the 203 

user to resubmit the corrected input file. For customization, each functionality provides users with 204 

a series of options. For example, when performing ECCO, users need to select a colormap, data 205 

scaling, and data transformation, if they want to run a default ensemble (Table 1), and if they want 206 

metabolic pathway enrichment files for each cluster that is identified. Detailed explanations of 207 

each functionality can be found on our Wiki, and example input and output files are provided for 208 

each functionality. All functionalities except ECCO can run locally with reasonable run times; we 209 

recommend running ECCO on multiple cores to ensure reasonable compute times. 210 

ECCO has several limitations that will be addressed in future releases. First, our initial release 211 

focuses on agglomerative hierarchical clustering and consensus-based ensemble clustering. Fu-212 

ture releases will incorporate additional clustering algorithms (e.g., K-means), and other ensemble 213 

approaches such as a selective clustering ensemble based on covariance ( Golalipour et al., 2021 ). 214 

Second, the current workflows are all run through the UI, limiting users to compute clusters with 215 

enabled UIs for larger datasets. Given the O( 𝑛 3) ( Bataineh, 2022 ) complexity of agglomerative hier-216 

archical clustering, to efficiently determine cluster solutions, a high-performance cluster is recom-217 

mended; thus, incorporating a non-UI workflow would improve usability. Finally, ECCO uses the 218 

optimal values of internal cluster metrics (e.g., minimum Davies-Bouldin index) to determine i) the 219 

number of clusters for a cluster solution, and 2) the ensemble cluster solution for a predefined 220 

number of clusters (100 or fewer). Future versions will allow users to input the number of clusters 221 

for each cluster solution, customize the number of clusters to consider, provide visuals of the inter-222 

nal cluster metric results, and incorporate statistical approaches to determining the significance 223 

of clusters (e.g., using the Gap Statistic, Tibshirani et al. (2001 )). We also plan to expand the UI by 224 

incorporating statistical modeling approaches and improving usability. We aim to achieve this by 225 

building a community-based coalition to add the latest functionalities to this UI. 226

Internal Cluster Metrics 302 

The ECCO UI currently supports three internal cluster metrics ( Golalipour et al., 2021 ) that quantify the optimal cluster solution. Most internal cluster metrics follow a similar approach, finding the ratios between inter-cluster separation (e.g., separation between cluster centers) and intra-cluster compactness (e.g., the spread of data objects in a cluster). The optimal clus-ter solution is determined by generating cluster solutions for 2–C clusters (where C ranges from 2 to N-1) and calculating the internal cluster metric for each solution. Depending on the metric, the optimal solution is either a maximum or a minimum. The current metrics include the Average Silhouette Width ( Rousseeuw, 1987 ), the Calinski-Harabasz index ( Cal-iński and Harabasz, 1974 ), and the Davies-Bouldin index ( Davies and Bouldin, 1979 ).

The ECCO UI supports all dissimilarity measures available in scipy, and incorporates two correlation-based measures. Typically, correlation-based metrics are transformed to a dis-similarity measure for clustering by either subtracting 1 or using a weighted square-root of one minus the correlation (Appendix - Figure 1A-B). However, these transformations create greater dissimilarity to negative correlations, observations that don’t correlate at all, mean-ing observations with minimal correlation will cluster while those with negative correlations won’t.
