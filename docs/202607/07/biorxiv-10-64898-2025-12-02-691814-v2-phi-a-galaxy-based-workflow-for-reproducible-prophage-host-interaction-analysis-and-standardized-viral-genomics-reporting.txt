Abstract 19 

Background: Viruses that infect bacteria, known as bacteriophages or phages, are 20 widespread in nature and play important roles in shaping microbial communities and 21 ecosystem functions. Some phages can integrate into bacterial genomes as “prophages”, 22 where they may influence the biology of their host by carrying genes that affect metabolism, 23 virulence, or environmental adaptation. Results: In this study, we introduce the Prophage-Host Interaction Toolkit (PHI), a user-27 friendly and automated workflow available through the Galaxy platform. PHI brings together 28 multiple established tools into a single, reproducible pipeline that identifies candidate 29 prophages, evaluates their quality, predicts host relationships, and characterizes key 30 functional genes. Background 44 Phages are viruses that infect bacterial cells. After infection, lytic viruses can replicate while 45 lysogenic phages can integrate their genome into the chromosome of their bacterial hosts [1]. 46 Prophages often carry auxiliary metabolic genes (AMGs) that affect host metabolic and 47 broader ecosystem functions [2, 3]. The automated discovery and comprehensive profiling 48 (e.g., taxonomic assignment, functional annotation, and life-cycle prediction) of phages 49

Existing workflows 51 typically focus on either identification and gene annotation [4, 5] or specific interaction 52 aspects [6], lacking a comprehensive approach that addresses a wide spectrum of phage-host 53 relationships within genomic data. 54 Several methods have advanced the field of phage identification and host prediction, such as 55 PHASTEST [5], VirSorter2 [7], and CHERRY [8] but they often provide limited information 56 on both host and phage perspectives, require extensive computational resources, or lack user-57 friendly interfaces, thereby limiting their use by the scientific community. 58 We present the Prophage-Host Interaction Toolkit (PHI), a comprehensive and automated 59 framework within the Galaxy [9] platform (e.g., publicly usable via https://usegalaxy.eu), for 60 the identification and profiling of phages within host genomes that unifies established tools 61 into a reproducible workflow. PHI overcomes the limitations of existing tools, such as the 62 complexity and difficulty that arise with installing and running multiple tools. PHI also 63 compiles all results in a single report, facilitating knowledge extraction and enabling 64 researchers from diverse backgrounds to benefit from bioinformatics applications without 65 requiring extensive technical training. 66 Key features of PHI include its modular architecture, allowing for easy updates and 67 customization. PHI incorporates tools for reproducible detection and contextual profiling of 68 candidate prophages, identification of phage-host pairs, and analysis of CRISPR spacer 69 relationships. Furthermore, it provides comprehensive visualization tools for depicting phage 70 genomic features and host interaction networks, facilitating the interpretation of complex 71 data. 72

Implementation 77 

Workflow. The workflow is implemented in Galaxy [9] and it is publicly available through 78 the Galaxy Europe server (https://usegalaxy.eu/u/maze/w/phi-toolkit). To achieve the full 79 functionality described in this manuscript, we pre-tailored the pipeline with established tools 80 and analyses that generate an HTML report through an R Markdown script. Additionally, the 81 flexibility of Galaxy allows for full customization of the pipeline. Any modification or 82 expansion of the pipeline is possible as long as the desired tools are available on the server 83 and the code used to generate the report is updated. 84 85 

Pipeline description. A simplified schematic of the workflow is shown in Figure 1. A more 86 detailed workflow schema produced by Galaxy’s workflow editor is available in the 87 Additional File 1: Figure S1). The PHI pipeline accepts bacterial genomes 88 in FASTA format as input files. These genomes are submitted in parallel to the following 89 host-analysis tools: CheckM2 1.0.2+galaxy1 using the CheckM diamond DB [10] to assess 90 the quality, GTDB-Tk 2.4.1+galaxy0 using the full DB release 220 [11, 12] to assign 91 taxonomy, Defense-Finder 2.0.1+galaxy1 using models 2.0.2 [13] to detect known anti-phage 92 systems, and finally geNomad 1.11.1+galaxy0 using reference data version 1.9 [14] to predict 93 and annotate prophages. Once a genome has been processed and prophages have been 94 identified by geNomad, several virus-analysis tools also run in parallel, which are: (i) 95 CheckV 1.0.3+galaxy0 using reference data version 1.5 [15] to evaluate the quality of 96 prophage genomes, (ii) dRep compare 3.6.2+galaxy1 using an ANI threshold of 0.95 [16] to 97

Unless stated otherwise, default parameters were used. The dRep 103 ANI threshold to form secondary clusters was set to 0.95 instead of the default 0.99 to 104 decrease clustering stringency. The database used by ABRicate was set to VFDB instead of 105 the default Resfinder since we are interested in virulence factors. Technically, CheckV and 106 VIBRANT can also predict prophages, but we decided to restrict this task to geNomad due to 107 its regular and active maintenance and to avoid redundancy in predictions. The workflow 108 concludes with the automated report generation via R Markdown, producing a structured 109 HTML summary (Additional File 2: Figure S2). The generated HTML report is organized 110 into multiple thematic sections that integrate host, prophage, and interaction-level analyses. 111 In addition to summary tables of genome quality, taxonomy, and prophage content, the report 112 includes interactive visualizations such as host-virus association networks, CRISPR spacer-113 protospacer matching outputs, and genome-level feature maps. These components allow users 114 to explore relationships between prophages and their predicted hosts, assess host range, and 115 evaluate genomic context in a unified framework. Tool versions, parameters, and database 116 releases are documented inside the workflow run to ensure reproducibility. 117 118

PHI first runs host-level analyses on all 119 submitted genome FASTA files and then triggers downstream viral analyses only when 120 geNomad reports candidate viral or prophage sequences. This 161 community is routinely used as a baseline for testing bioinformatics analyses and data 162 interpretation. As we were focusing on phages, we downloaded the FASTA sequences of the 163 complete genomes of 22 bacterial strains from the National Centre for Biotechnology 164 Information (NCBI), except for the reference genome NC_010067.1, which was marked as 165 "Record suppressed". Additionally, this resource-use analysis should be interpreted as computational 183 profiling of the workflow rather than as a predictive-performance benchmark of the 184 underlying tools. 185 To further evaluate scalability, we performed an additional analysis in which individual tool 186 runtimes were grouped by input file-size intervals, and mean runtime values were calculated 187 for each interval (Additional File 4: Table S2). This analysis showed that runtime did not 188 increase linearly with file size for most tools. Lightweight tools such as ABRicate remained 189 below one minute on average across the tested intervals, whereas tools involving larger 190 database searches or more complex sequence characterization, including geNomad, CheckV, 191 and DefenseFinder, showed greater runtime variability. This suggests that runtime is 192 influenced not only by input file size, but also by sequence composition, contig structure, 193 number of detected viral regions, and fixed initialization costs. iPHoP showed relatively 194 stable runtime across the tested small-file intervals but remained the most memory-intensive 195 step, indicating that memory availability rather than runtime is the main practical constraint 196 for full PHI analyses. Batch-level tools such as GTDB-Tk and CheckM2 should be 197 interpreted separately because they process the complete submitted genome set 198 simultaneously rather than individual genome files. 199 Implementation in Galaxy improves accessibility because usegalaxy.eu provides public 200 access to the required computational infrastructure. 201

Detection and Distribution of Antiviral Defense Systems Across Samples 213 PHI integrated DefenseFinder outputs to summarize the presence of prokaryotic antiviral 214 defense systems across multiple genome assemblies (Table 2). The results revealed a diverse 215 array of defense mechanisms distributed unevenly among the samples. The number of 216 detected defense systems per genome ranged from 3 to 24, with NC_021184.1 exhibiting the 217 highest count (24 systems) and NC_014168.1 presenting the fewest (3 systems). In terms of 218 diversity, NC_021184.1 displayed the greatest richness in both system types (13 unique 219 types) and subtypes (n=18), followed by NC_019904.1, which contained 12 system types and 220 13 subtypes. Conversely, samples such as NC_014168.1 showed limited diversity, with only 221 2 unique types. Gene content associated with defense systems also varied substantially. The 222 sample NC_021184.1 encoded the largest number of defense-related genes (n=75), while 223 NC_014168.1 had the fewest (n=4). These results illustrate how PHI integrates and reports 224 DefenseFinder outputs to enable comparison of antiviral defense repertoires across genomes. 225 The observed variation highlights the level of detail that can be captured using the 226 DefenseFinder module within the Phage Toolkit. 227

Conclusions 256 The PHI Toolkit, available through the Galaxy platform, addresses a critical bottleneck in 257 phage research by enabling worldwide access to powerful, yet accessible, computational 258 analyses for both bioinformatics experts and non-experts. Rather than introducing novel 259 predictive methods and algorithms, PHI consolidates tools into a streamlined web interface 260 with a modular, cloud-hosted architecture, eliminating the need for local hardware and 261 advanced bioinformatics expertise. Researchers can therefore avoid manual data wrangling 262 and devote their efforts to biological discovery rather than software installation, maintenance, 263 or resource management. Because each module is version-tracked and can be updated, users 264 can rely on established and actively maintained tools without manual upgrades, while still 265 retaining the flexibility to swap in new tools as the field evolves. Furthermore, the 266 integration of these results within a single interactive report facilitates biological 267 interpretation by linking host identity, prophage content, genome context, and functional 268

When combined with prophage annotations, virulence 272 screening, AMG detection, and host prediction outputs, this integrated structure enables rapid 273 identification of biologically relevant patterns that would be difficult to infer from individual 274 result files alone. Future development of PHI will focus on expanding the workflow with 275 additional prophage-detection, host-prediction, annotation, and visualization modules as new 276 methods become available. Beyond general phage–host interaction studies, PHI may support 277 applied microbiome research by enabling systematic screening of prophage content, 278 virulence-associated genes, auxiliary metabolic genes, and host defense systems in 279 biotechnologically relevant bacteria. In the future, this could include microbial strains 280 considered for bioinoculants or low-risk pesticide applications [24, 25], provided that 281 dedicated validation datasets are used and the outputs are interpreted as part of a broader 282 strain-characterization and risk-assessment framework. 283
